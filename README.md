# TEM/SEM Image Segmentation Data Pipeline

This repository contains a reproducible ETL (Extract, Transform, Load) pipeline for my electron microscopy image segmentation project. The pipeline retrieves three publicly available microscopy datasets, organizes the raw image and segmentation-label data, and creates a unified SQLite database for later image-processing and machine-learning analysis.

The long-term goal of the project is to develop and evaluate methods for nanoparticle segmentation and particle-size analysis from TEM/SEM images.

## Datasets

The database combines data from three microscopy datasets.

### 1. EMPS Dataset

The EMPS dataset contains heterogeneous TEM and SEM images with manually annotated particle segmentation maps.

- Images used: 465
- Training images: 366
- Test images: 99
- Image format: PNG
- Segmentation maps: PNG instance masks
- Source: https://github.com/by256/emps

The original train/test split supplied with the dataset is preserved.

### 2. HRTEM Generalization Dataset

The HRTEM Generalization dataset contains high-resolution TEM images of different nanoparticle materials.

For reproducibility and manageable data size, this project uses a deterministic 30-image subset:

- Ag: 10 images
- Au: 15 images
- CdSe: 5 images
- Total: 30 images

The subset is selected using a fixed random seed (`random_state=42`), so repeated runs select the same records.

The original source-folder hierarchy is retained because some filenames occur in more than one source folder.

Sources:

- https://doi.org/10.7941/D1SP93
- https://portal.nersc.gov/project/m3795/hrtem-generalization/
- https://github.com/ScottLabUCB/HRTEM-Generalization

### 3. Co3O4 Dataset

The Co3O4 dataset contains microscopy images and corresponding one-hot encoded segmentation labels stored in HDF5 files.

- Images used: 256
- Image dimensions: 512 x 512 pixels
- Image file: `training_images.h5`
- Label file: `training_labels.h5`
- Source: https://zenodo.org/records/14927582

## Running the ETL Pipeline

### Requirements

The reproducible workflow uses:

- Git
- Just
- Podman

Python and the required Python packages are installed inside the container defined by the `Containerfile`.

### Run

From the repository root, execute:

```bash
just
```

The `Justfile` builds the container and runs the Makefile inside it.
**Note:** The first run downloads several gigabytes of public microscopy data and may take considerable time depending on network speed. Interrupted Co3O4 downloads can be resumed. Subsequent runs reuse successfully downloaded data.
The workflow is:

```text
Justfile
   |
   v
Containerfile / Podman
   |
   v
Makefile
   |
   +--> download_EMPS.py
   |
   +--> download_HRTEM.py --demo
   |
   +--> download_Co3O4.py
   |
   v
create_database.py
   |
   v
Data/Database/microscopy.db
```

The download scripts check whether the required data already exist and are complete before downloading them. Repeated runs reuse existing valid data rather than duplicating the raw datasets. The database is recreated deterministically on each run, producing the same expected 751 records.

## ETL Process

### Extract

The download scripts retrieve or verify the required source datasets:

```text
Scripts/download_EMPS.py
Scripts/download_HRTEM.py
Scripts/download_Co3O4.py
```
Large Co3O4 downloads support retry/resume behavior, and downloaded files are validated against the file sizes reported by the Zenodo record.
### Transform

Dataset-specific information is standardized into a common representation. This includes file paths, label types, microscopy metadata, material information, image dimensions, physical scale information where available, and dataset split information.

### Load

`Scripts/create_database.py` creates the unified SQLite database and loads records from all three datasets.

A successful run should report:

```text
EMPS  = 465
HRTEM = 30
Co3O4 = 256
TOTAL = 751
```

## ETL Part II — tensors for segmentation

Run `just pipeline` to acquire data, recreate the 751-record SQLite database,
and export **EMPS-only** binary semantic-segmentation tensors to:

- `data/inputs/train.safetensors`
- `data/inputs/eval.safetensors`
- `data/inputs/manifest.json` (sample IDs, source paths, group IDs, folds, split method)

Run `just check` to validate all tensor shapes, types, masks, database IDs,
training/evaluation group separation, duplicate-image separation, and 5-fold
cross-validation group assignments. `just` by itself still performs Part I.

Tensor images are 8-bit grayscale `[N, 1, 256, 256]`; binary masks have the
same shape and contain 0/1. Conversion uses bilinear interpolation for images
and nearest-neighbor interpolation for binary masks. Intensity normalization
(e.g. `images.float() / 255`) belongs in the training code.

**Group splitting:** The script groups samples sharing a filename-family prefix
or exactly identical image pixels. If EMPS's supplied train/test assignment
keeps these derived groups separate, it is retained; otherwise a seeded
80/20 group split is created. Five seeded folds are assigned to **training
groups only**. This is an auditable safeguard against known/derived overlaps,
**not proof of acquisition-level independence**: EMPS does not provide verified
acquisition group IDs in the Part I database. Check original source metadata
before interpreting evaluation results as fully acquisition-independent.

Example PyTorch consumption (PyTorch is installed in your training environment,
not required to generate or validate the files):

```python
from safetensors.torch import load_file
from torch.utils.data import TensorDataset, DataLoader
s = load_file('data/inputs/train.safetensors')
loader = DataLoader(TensorDataset(s['images'].float() / 255,
                                  s['masks'].float()), batch_size=8, shuffle=True)
```

The tensor files are generated artifacts and are excluded from Git. Re-running
`just pipeline` overwrites them deterministically from source data.
## Model Training and Automated Report

This project extends the reproducible microscopy ETL pipeline to train and evaluate a U-Net model for nanoparticle segmentation in transmission electron microscopy (TEM) images.

### Model and Dataset

- **Dataset:** EMPS electron microscopy images with corresponding segmentation masks.
- **Architecture:** A compact U-Net implemented using PyTorch.
- **Training:** Binary cross-entropy (BCE) combined with soft Dice loss, optimized using Adam.
- **Data splitting:** 366 training-set image/mask pairs, with a group-aware validation subset, and 99 held-out test pairs.
- **Evaluation metrics:** Dice coefficient and Intersection over Union (IoU).

### Baseline Comparisons

The U-Net is evaluated against two reference methods:

1. **Negative control:** An all-background segmentation predictor.
2. **Classical comparator:** Otsu thresholding, a traditional image segmentation method.

### Automated Pipeline

The entire pipeline can be executed using:

```bash
just
```

This command runs the data preparation, database creation, tensor generation, model training, evaluation, and report generation steps.

The pipeline automatically generates:

- `artifacts/results.json` — Model evaluation results.
- `artifacts/loss.png` — Training and validation loss curves.
- `artifacts/predictions.png` — Example segmentation predictions compared with ground truth and Otsu thresholding.
- `report.pdf` — Automatically generated report containing the methodology, evaluation results, figures, and discussion.

### Model Performance

In the 30-epoch experiment, the U-Net achieved the following results on the held-out test set:

| Method | Mean Dice | Mean IoU |
|---|---:|---:|
| U-Net | 0.6173 | 0.4746 |
| All-background negative control | 0.0000 | 0.0000 |
| Otsu thresholding | 0.2979 | 0.2338 |

These results demonstrate that the trained U-Net outperformed both comparison methods. Future improvements may include data augmentation, architecture optimization, and additional training experiments.

**Note:** The default number of training epochs is configured in `src/train_report.py` and can be overridden using the `TEM_EPOCHS` environment variable.
